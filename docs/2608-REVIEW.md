## 2. 수정 프롬프트

아래 프롬프트를 위에서부터 하나씩 실행. 한 번에 여러 개를 섞지 않기.

### 프롬프트 1 - API 배포 방식 정리

```text
이 프로젝트의 API 구조를 Vercel 배포 기준으로 점검하고 수정해줘.

현재 상황:
- 프론트엔드는 Vite 기반이야.
- AI 질문 생성 API는 Express 서버 또는 `/api` 경로를 사용해.
- 로컬에서는 프록시로 동작하지만, Vercel 배포 후에도 같은 방식으로 동작하는지 확인이 필요해.

목표:
- Vercel에서 동작 가능한 API 구조로 정리해줘.
- 필요한 경우 Vercel Serverless Function 구조로 옮겨줘.
- 프론트엔드 API 호출 경로도 배포 기준에 맞게 정리해줘.

확인:
- `npm run build`
- 로컬에서 API 요청 테스트
- 배포 시 필요한 환경변수 목록 정리
```

### 프롬프트 2 - 대시보드 CTA 추가

```text
대시보드에서 면접 연습 기능으로 바로 이동할 수 있게 수정해줘.

목표:
- 로그인 후 대시보드에 들어오면 `면접 연습 시작` 버튼이 보여야 해.
- 버튼을 누르면 `/interview`로 이동해야 해.
- 이미 연습 기록이나 프로필 정보가 있으면 대시보드에 함께 보여줘.

조건:
- 기존 레이아웃을 크게 바꾸지 마.
- 초보 사용자가 다음 행동을 바로 알 수 있게 문구를 짧게 정리해줘.
- 수정 후 `npm run build`, `npm run lint`, `vitest --run`으로 확인해줘.
```

### 프롬프트 3 - Supabase SQL 재실행 가능하게 정리

```text
Supabase SQL 파일을 다시 실행해도 오류가 나지 않도록 정리해줘.

목표:
- `create table if not exists` 사용
- policy 생성 전 기존 policy 처리
- index 생성 시 `if not exists` 사용
- RLS 설정이 빠지지 않게 확인

완료 후:
- 어떤 테이블과 policy가 필요한지 표로 정리해줘.
- Supabase SQL Editor에서 실행할 순서도 알려줘.
```

### 프롬프트 4 - 프로필 빈 상태 처리

```text
프로필 조회 로직에서 데이터가 없을 때와 실제 에러가 났을 때를 구분해줘.

목표:
- 아직 온보딩을 하지 않은 사용자는 온보딩 화면으로 이동
- 네트워크 오류나 권한 오류는 에러로 표시
- `.single()` 사용이 문제를 만들면 `.maybeSingle()` 또는 동등한 처리로 변경

확인:
- 새 계정 로그인
- 온보딩 완료 계정 로그인
- 프로필 row가 없는 계정 로그인
```
